1. 배경

수백 개 함수에서 시작점을 찾는 비용을 줄입니다. API는 요청 경로, 화면은 페이지 경로, 스크립트는 실행 명령·파일에서 탐색합니다.

확인된 사실

현재 UI는 전체 함수 평면 목록입니다. roots와 groupPath, 함수 ID 참조 및 블록 렌더러는 이미 있습니다.

계획상 선택

기존 함수 저장 구조 위에 라우트별 진입점 정보를 더합니다. 호출되지 않는 함수라는 이유로 시작점으로 추정하지 않습니다.

2. 직관

사용자는 진입점부터 고릅니다

GET /orders/:id → 등록된 handler 선택 → 기존 함수 블록 펼치기

/orders → 페이지 component 선택 → 함수 블록 또는 Vue 파일 원문 확인

seed → scripts/seed.ts → 파일 최상위 블록 → main() 함수 펼치기

동일 함수가 두 URL에 등록되면 목록에는 두 진입점, JSON에는 함수 정의 하나만 존재합니다.

4. 실행·의존 흐름

  1. scripts/bin/--entry의 적격 TS/TSX 파일을 모은 뒤 기존 Program·Checker와 함수 인덱스를 구성합니다.
  2. 프레임워크 import와 등록 선언을 확인하고 정적 경로·대상을 연결합니다.
  3. 함수 ID·스크립트 module ID 또는 안전하게 수집한 원문 위치를 진입점에 기록합니다.
  4. JSON을 검증하고 기존 CLI로 JSON·내장 HTML을 함께 저장합니다.
  5. 진입점에서 대상 함수를 선택해 기존 블록을 탐색합니다.
등록 관계와 실행 순서는 다릅니다Express middleware·React loader/action·event/effect를 하나의 동기 실행 흐름으로 합치지 않습니다. 동적 경로는 원문과 미해결 이유를 남깁니다.

5. 핵심 선택

작게 추가

v1에 optional entrypoints·modules·moduleCoverage. 함수 정의와 호출 ID, 수동 roots를 재사용합니다. 플러그인 registry·DB·서버는 추가하지 않습니다.

대안인 함수별 URL 필드는 복수 경로와 다중 handler 표현이 부족합니다.

지원 범위 명시

단순 tsx/ts-node 명령·TS bin·명시 파일을 지원합니다. shell 실행, JS 원본 매핑, import 초기화 순서 추정은 후속입니다.

API는 NestJS·Express, 페이지는 React Router·Vue Router부터 시작합니다. Vue SFC 내부 흐름과 Next/TanStack/Nuxt는 후속입니다.

자동 탐지 실패는 수동 root로 보완하며 모르는 실행 결과를 추정하지 않습니다.

호환성과 정확성구형 JSON도 열 수 있습니다. 진입점 partial 진단은 기존 CLI exit 2 정책에 반영합니다. 실제 배포 URL 완전성을 보장하는 기능은 아닙니다.
