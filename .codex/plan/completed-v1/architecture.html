1. 배경

호출 관계만으로는 함수 안에서 어떤 조건으로 무엇이 반복되는지 읽기 어렵다. 소스의 구조를 저장하고, 같은 구조를 중첩 블록으로 보여준다.

확인된 현재 상태

M0 문서만 존재. 제품 코드·패키지·빌드 산출물은 없고 main에 커밋도 없다.

계획의 판단 기준

함수 정의는 한 번 저장한다. 실제 값·실행 분기·비동기 완료 순서를 추측하지 않는다.

2. 직관

outer(inner(amount))는 inner 호출을 먼저 읽고 outer를 읽는다. 인자 inner(amount)의 원문은 유지한다. 주석 설명은 코드 인자와 별도 데이터다.

호출 참조와 구문 중첩은 다르다분기·반복은 본문 안에 중첩한다. 다른 함수는 ID로 참조하고 펼칠 때 읽는다. 재귀는 조상 함수 ID에서 멈춘다.

4. 실행·의존 흐름

01

분석 경계

tsconfig와 ignore로 내보낼 소스를 정한다. Program/TypeChecker로 함수와 호출을 읽고 제어 구조를 보존한다. 대상 코드를 실행하지 않는다.

02

저장 경계

공용 검증기로 JSON을 확인하고 임시 파일을 rename한다. 실패하면 이전 결과를 보존한다. 미지원·미해결은 partial과 진단으로 표시한다.

03

화면 경계

File API → 같은 검증기 → 함수 선택 → 중첩 블록 → 호출 펼침. 원문과 주석을 텍스트로 표시한다.

정적 분석의 한계외부 호출·런타임 DI·콜백 실행 시점은 확정하지 않는다. await는 대기 위치만 보여준다. complete는 지원 범위의 분석 완전성이다.

5. 핵심 선택

선택이유대안과 tradeoff
Compiler APITS 설정·심볼 해석 활용Tree-sitter보다 TS에 집중. 버전 호환 검증 필요
단일 패키지 + JSON저장과 공유 계약 최소화DB·workspace 분리는 보류. 대용량은 M6 측정
React + standalone HTML함수 구조를 재귀 UI로 표시JCEF bridge 제외. 단일 파일 번들 검증 필요
검증기만 공유CLI와 UI 두 사용처가 확정범용 framework·resolver interface는 만들지 않음
